# Project Master Plan — Public / Sanitized

## Planning basis

- Delivery window: 240 calendar days
- Delivery model: Hybrid Agile + Stage Gate
- Working schedule baseline: 1 Oct 2026
- Formal checkpoints: Day 30 / Day 120 / Day 210 / Day 240
- This public plan is a sanitized management view, not the complete internal `.mpp` schedule.

## Public milestone calendar

| Milestone | Contract day | Planning date* | Exit criteria — public summary |
|---|---:|---|---|
| M1 — Phase 1 submission | D30 | 30 Oct 2026 | Project management, kickoff, risk package ready |
| M2 — Phase 2 submission | D120 | 28 Jan 2027 | Requirements/design/prototype/test-planning baseline approved |
| M3 — Phase 3 submission | D210 | 28 Apr 2027 | Platform developed and major verification/acceptance evidence compiled |
| M4 — Final / Closeout | D240 | 28 May 2027 | Training, go-live, handover, final documentation complete |

* Planning dates assume 1 Oct 2026 as the baseline start and must be recalculated if the contractual start date changes.

## Work breakdown — public view

### Phase 1 — Mobilization and governance
- Project organization and kickoff
- Project Management Plan
- Risk Management Plan
- Communication, issue, change, and escalation approach
- Document control and delivery governance
- Initial stakeholder and integration discovery

### Phase 2 — Requirements, design, prototype, and environments
- Stakeholder workshops and business-process discovery
- As-Is / To-Be workflow definition
- Functional requirements for the 11 capability areas
- Non-functional, security, privacy, audit, and data requirements
- SRS, architecture, data design, API/interface design
- UX/UI and critical-flow prototype
- Test strategy and acceptance approach
- Development/UAT cloud and DevOps baseline

### Phase 3 — Build, integration, and acceptance
- SSO / MFA / IAM / RBAC
- configuration and notifications
- API/integration services
- file ingestion, OCR, field extraction, data quality
- transaction analysis and graph visualization
- case management
- refund and asset-return workflows
- chatbot, reporting, dashboard
- SIT, defect remediation, security/performance testing, UAT

### Phase 4 — Production readiness and closeout
- production readiness and security hardening
- backup/restore and rollback validation
- cutover / go-live preparation
- manuals, training, knowledge transfer
- production deployment and early-life support
- source/configuration/document handover
- final report and closeout

## Management cadence

- weekly project status review
- two-week development/demo rhythm where applicable
- monthly steering / executive checkpoint
- continuous RAID management
- TOR traceability and document-quality review before each contractual submission

## Excluded

Task-level dependencies, resource loading, security-sensitive implementation details, system-specific integration names, environment information, and operational notes are intentionally excluded from this public view.
