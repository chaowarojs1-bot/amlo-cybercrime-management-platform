# TOR Summary — Public / Sanitized

## Purpose

The project aims to develop an information platform for managing data and operational workflows related to technology-enabled crime, including case handling, transaction analysis, and processes supporting the return of assets to affected persons.

This document is a public, sanitized summary derived from the project TOR working knowledge. It is not a substitute for the official TOR or contract.

## Functional capabilities

1. Single Sign-On (SSO)
2. Configuration Management
3. Notification Service
4. Data Integration
5. Transaction Analysis & Graph Visualization
6. Case Management
7. Refund Request
8. Asset Return Distribution
9. Chatbot
10. Reporting
11. Dashboard / Data Visualization

## Data and document processing

Publicly described capabilities include file ingestion for common document/data formats, OCR for Thai/English documents and mixed numeric content, key-field extraction, data validation and quality controls, API/web-service integration, ETL/ELT-style transformation, and auditability.

## Security requirements — public level

Enterprise expectations include MFA, centralized identity/access control, RBAC, encryption in transit and at rest, logging/monitoring/audit trails, separation of development/test-UAT/production environments, and security testing before final acceptance.

Detailed infrastructure topology, credentials, configuration values, security findings, and operational security procedures are intentionally excluded.

This summary deliberately omits details that could expose internal systems, operational dependencies, personal/case information, or security-sensitive implementation details. The official project documentation remains authoritative.
